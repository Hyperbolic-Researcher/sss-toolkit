# 一、环境类问题

## A1. bat 中文乱码

**症状**：双击 bat，满屏

```
'??' 不是内部或外部命令，也不是可运行的程序或批处理文件。
```

**原因**：Windows cmd 默认按 **GBK(936)** 读取批处理文件。
如果文件存成 UTF-8，中文会被解析成乱码，**破坏语句结构**，每一行都被当成命令。

> 注意：加 `chcp 65001` **没用** —— cmd 在读取文件阶段就已经用 GBK 解析了。

**解法**（三条一起用）：

1. **bat 内容含中文 → 必须存 GBK 编码**
   ```python
   open('x.bat', 'w', encoding='gbk', newline='\r\n').write(content)
   ```
2. **bat 里的路径必须用反斜杠**
   Windows 的 `cd /d` 不认 `C:/Users/...`，会报「文件名、目录名或卷标语法不正确」。
3. **桌面启动器保持纯 ASCII**，只 `call` 一个英文名的 bat
   避免「UTF-8 文件里写中文文件名 → 解析失败」

**当前实现**：
- `start_webui.bat` → GBK 编码 + 中文提示 + Python 探测（**唯一有逻辑的启动器**）
- `启动网页界面.bat` → 薄壳，只 `call start_webui.bat`
- 桌面 `SSS工具.bat` → 纯 ASCII + 反斜杠 + 只 call 英文名

## A2. 窗口一闪而过

**症状**：双击 bat 后黑窗口闪一下就没了，什么也看不到。

**原因**（按概率排序）：

1. **端口被占用** —— 已有服务在跑，新进程 bind 失败直接退出
2. Python 缺失或路径不对
3. 脚本本身报错

**解法**：

- `start_webui.bat` 已内置检测：
  - 检查 `python` 是否存在
  - 用 `netstat` 检查 8765 端口，被占时提示并提供一键清理
  - 服务退出后 `pause`，不会闪退
- 想自己看错误：**在 cmd 里手动运行 bat**，窗口会停住

## A3. 多个 Python 导致缺依赖

**症状**：

```
C:\Users\xxx\AppData\Local\Programs\Python\Python311\python.exe:
No module named yt_dlp
```

**原因**：机器上有多个 Python，`python` 命令走 PATH 命中了**没装依赖**的那个。

实测本机情况：

| Python 路径 | 有 yt-dlp |
|---|---|
| `.workbuddy/binaries/python/envs/default/Scripts/python.exe` | ✅ |
| `.workbuddy/binaries/python/versions/3.13.12/python.exe` | ❌ |
| `AppData/Local/Programs/Python/Python311/python.exe` | ❌（PATH 优先） |

**解法**：`start_webui.bat` 会依次探测候选，用
`python -c "import yt_dlp"` 实测，选第一个能用的。

如果全都不行，执行：

```bash
pip install -U yt-dlp openpyxl imageio-ffmpeg
```

## A4. 服务「重启成功」但改动没生效

**症状**：改完代码重启服务，页面行为还是旧的；`curl` 返回 200 但内容没变。

**原因**：旧进程没真正退出，占着 8765 端口。
新进程启动失败后**静默退出**，而工具报告「已停止」。

**解法**：重启后**必须验证进程创建时间**：

```powershell
Get-CimInstance Win32_Process -Filter "Name='python.exe'" |
  Where-Object { $_.CommandLine -match 'webui' } |
  ForEach-Object { "PID=$($_.ProcessId) 启动=$($_.CreationDate.ToString('HH:mm:ss'))" }
```

时间不是刚才 → 端口被旧进程占着 → 先 `Stop-Process` 再启动。

> 这是本项目最浪费时间的一个坑：**15:34 之后的改动全部没生效**，
> 却以为改了、还抱怨「修了三次还是错」。

**解法**：不用 tkinter，改用 **ctypes 直接调 Win32 API**：

## A6. 沙箱环境批量删文件卡死

**症状**：批量下载时「取 20 个只成 1 个」，进程无响应。

**原因**：yt-dlp 合并后会删除中间流文件。在某些沙箱/托管环境里，
单进程累计删除满 50 个文件会被安全机制拦截并卡死。

**解法**：加 `--keep-video`，中间文件由脚本用 `shutil.move` 移到隔离区。
**移动不触发拦截。**

```python
if adv.get("keep_video", True):
    args.append("--keep-video")
```

## A7. 多个启动器各自实现，改一个没用

**症状**：主启动脚本明明修好了，用户双击还是失败；
「双击没反应」被反馈了**两次**才定位到真凶。

**原因**：仓库里同时存在 **4 个启动 bat**，其中两个中文名的
（`启动网页界面.bat` / `启动网页界面_手机版.bat`）各自写了一份
`python webui.py`，**没有做 Python 探测**。
用户顺手点的是中文名那个 → 命中没装 yt-dlp 的 Python → 直接退出。

```
启动网页界面.bat        ← 用户更可能点这个，但它是坏的
启动网页界面_手机版.bat  ← 同上
start_webui.bat        ← 唯一修好的
命令行.bat             ← 也是裸 python
```

**根因不是编码、不是端口，是「同一件事有 4 份实现」。**
修了 A1/A2/A3 之后仍然复现，就是因为改的不是用户实际执行的那一份。

**解法：单一入口 + 薄壳转发**

```bat
REM 启动网页界面.bat  —— 只做转发，不写任何逻辑
@echo off
chcp 936 >nul 2>&1
cd /d "%~dp0"
call "%~dp0start_webui.bat" %*
```

- 逻辑只保留在 `start_webui.bat` 一处
- 重复的 `启动网页界面_手机版.bat` **直接删除**（主脚本本来就监听局域网）
- Python 探测链：`.venv\Scripts\python.exe` → 托管环境 → `python`
  每个候选都先跑 `python -c "import yt_dlp"` 验一遍，能 import 才用

**验证方式（别只改不验）**：

```bash
cmd //c start_webui.bat &            # 后台起
sleep 8
curl -s -o /dev/null -w "%{http_code}" http://127.0.0.1:8765/   # 必须 200
```

**通用教训**：

> 同一个动作有第二个入口，就一定会有一个入口是坏的。
> 要么合并成一个，要么让第二、第三个只做转发。

# 二、下载类问题

## B1. 只下到 360p

**排查顺序（不能乱）**：

### 第 1 步：查 POT 服务

```bash
curl --noproxy '*' -s -m 3 http://127.0.0.1:4416/ping
```

无响应 → POT 停了。**先重启它**，90% 的「360p 问题」是它引起的。

POT 停止会导致格式解析不完整，只剩单文件 `format 18`（360p）。
重启后**同一节点、同一 IP** 立刻恢复完整格式列表。

### 第 2 步：查源站真实上限

```bash
yt-dlp -F "<url>"
```

- 看到 `399` / `248` / `137` / `1920×1080` → 源站有高清
- 只有 `18` → 源站/节点限制

### 第 3 步：才怀疑节点

机房 IP 可能被 YouTube 降级。换住宅 IP。

---

**格式 ID 速查**（容易记错）：

| 用途 | AV1 | VP9 | H.264 | 规格 |
|---|---|---|---|---|
| 视频 | **399** | 248 | 137 | 1920×1080 |
| 视频 | **398** | 247 | 136 | 1280×720 |
| 视频 | 397 | 244 | 135 | 854×480 |
| 音频 | — | **251** | 140 | Opus 160k / AAC 128k |
| 混合 | — | — | **18** | 360p 单文件（降级标志） |

## B2. 字幕 HTTP 429

**症状**：抓字幕全部 `HTTP Error 429: Too Many Requests`

**已验证无效的方案**（别重复试）：

- 换 IP / 换节点 ❌
- 换 player_client（tv / web / android）❌
- 换字幕格式（vtt / json3 / ttml / srv1）❌
- 重启 POT 服务 ❌

**这是字幕 CDN 级别的限流**，与 IP、client 都无关。

**有效替代**：**从视频简介（description）提取歌词**

官方常把歌词写在简介里：
```
LYRICS:
The baby in the bath goes splash, splash, splash.
...
```

`core/lyrics.py` 的 `fetch_desc_fallback()` 就是干这个的。

**局限**：只有文本，没有时间轴。

## B3. 只有分离流没有成品

**症状**：目录里只有 `.f399.mp4` + `.f251.webm`，没有完整 mp4，**而且不报错**。

**原因**：yt-dlp 合并环节静默失败（错误被 `capture_output` 吞了）。

**解法**：手动用 ffmpeg 合并

```bash
ffmpeg -y -i "video.f399.mp4" -i "audio.f251.webm" \
  -c copy -map 0:v:0 -map 1:a:0 -movflags +faststart out.mp4
```

合并后**必须校验分辨率**，低于原文件就丢弃。

## B4. .part 未完成文件

**症状**：目录里有 `xxx.f399.mp4.part`，双击打不开。

**原因**：下载被中断（服务重启、手动取消、网络断）。

`.part` 是未完成的临时文件 —— **没有音轨、没有容器尾**，任何播放器都打不开。

**解法**：

- `_sweep_intermediates()` 会自动把 `.part` / `.ytdl` / `.fNNN` 移到 `_quarantine`
- 清理规则已包含带序号后缀：`\.f\d+(-\d+)?\.`

## B5. 老视频高清不可用

**症状**：重下某个视频，画质反而比之前的低。

**原因**：YouTube 侧的高清转码已被清理。

实测案例：

| 视频 | 本地 | 源站现在 |
|---|---|---|
| Five Little Monkeys | 1080p | 720p |
| Seven Steps | 1080p | 360p |

**判断原则**：

```
本地 ≥ 1080p        → 不用重下
本地 < 1080p → 查源站 → 源站不高于本地：保持原文件
                       → 源站更高：可以重下
```

**不查源站就重下，等于用更差的文件换掉更好的。**

## B6. 音频格式兼容性

**症状**：视频在 Windows 自带播放器打不开。

**原因**：AV1 + **Opus** 的 MP4（`major_brand=isom`）。
Opus 在 MP4 容器里 Windows 自带播放器不认。

**解法**：音频强制优先 AAC

```
bestvideo[height>=1080]+bestaudio[ext=m4a]
```

视频仍保留 AV1（体积只有 H.264 的 1/3），只把音频换成 AAC，体积几乎不变。

# 三、Web 界面问题

## C1. 列表排版错乱

**症状**：标题被压成 `W...`，勾选框/时长/大小各占一行。

**根本原因**：`<table>` + `colgroup` + `table-layout:fixed` + `text-overflow` 这套组合太脆弱。

**踩过的错误尝试**：
1. 加 `<colgroup>` 固定列宽 → 无效
2. 去掉 `max-width:0` → 仍无效

> `max-width:0` 是 `table-layout:auto` 时代的技巧，
> 在 `fixed` 模式下会把列宽算成 0。

**最终解法：放弃 table，用 flex**

```html
<div class="lrow">
  <div style="width:26px;flex:none">复选框</div>
  <div class="ttl" style="flex:1;min-width:0">标题</div>
  <div class="dur" style="width:64px;flex:none">时长</div>
  <div class="size" style="width:92px;flex:none">大小</div>
</div>
```

```css
.lrow{display:flex;align-items:center;gap:10px;padding:8px 10px}
.lrow .ttl{flex:1;min-width:0;white-space:nowrap;overflow:hidden;text-overflow:ellipsis}
```

**`flex:1 + min-width:0`** 是 ellipsis 的标准组合，不受表格列宽算法干扰。

## C2. 页面出现裸露标签

**症状**：页面底部出现文字 `div>`

**原因**：删代码时切片位置算错，残留了半截标签，破坏 HTML 结构。

**解法**：

1. 立即清理残留
2. **用 HTML 解析器验证标签配对**：
   ```python
   from html.parser import HTMLParser
   # 统计 <div> / </div> 深度，最终深度应为 0（或预期的嵌套层数）
   ```
3. 检查「不在标签内的裸文本」：
   ```python
   text = re.sub(r'<[^>]*>', '', html)
   ```

## C3. 歌词/Excel 范围不对

**症状**：目录里有 7 个视频，歌词只处理了 2 个；Excel 只有 2 行。

**原因**：范围筛选写成「`videos.txt` ∩ 目录内 mp4」。
但 `videos.txt` 可能只有 2 条（某次批量只写了 2 条）→ 交集只有 2 个。

**核心认知**：

> **清单回答「频道有什么」，目录回答「我下了什么」。**
> 「下载完成后的后续操作」必须用后者。

**解法**：以**目录内 mp4 为唯一依据**，清单只用来补标题：

```python
for f in glob.glob(os.path.join(out_dir, "*.mp4")):
    vid = re.search(r"\[([A-Za-z0-9_-]{11})\]", f).group(1)
    if vid in title_map:
        found.append(title_map[vid])
    else:
        # 清单里没有 → 从文件名反推标题
        title = re.sub(r"\s*\[[A-Za-z0-9_-]{11}\]\.mp4$", "", os.path.basename(f))
        found.append((vid, "", "0", title))
```

## C4. 打开目录无反应

**症状**：点「打开目录」/「打开所在文件夹」，API 返回 `{"ok": true}`，但窗口不弹。

**原因**：**服务进程没有桌面会话**。

- 用命令行/后台启动的服务 → 无桌面 → `os.startfile` / `explorer` 静默失败
- **用户双击 bat 启动** → 有桌面 → 正常

**解法**：

1. 用户自己双击 `start_webui.bat` 启动
2. 已提供「复制路径」按钮兜底（粘贴到资源管理器地址栏）

## C5. 前端 JS 报 `Cannot read properties of null`

**症状**：解析成功但页面同时报错。

**原因**：删了 HTML 元素，但 JS 里还引用它（`$('xxx').dataset`）。

**解法**：
- 删 HTML 元素后**必须全文搜 JS 里的引用**
- 用 `grep -c "元素ID"` 确认清零
- **每次改 JS 后跑 `node --check`**：
  ```bash
  node --check extracted.js
  ```
  能抓到 `lyrics-desc: 'xxx'` 这种（`-` 被当减号）语法错误。

## C6. 变量遮蔽导致 `UnboundLocalError`

**症状**：`UnboundLocalError: cannot access local variable 'ch'`

**原因**：模块别名 `from . import channel as ch`，
但函数内又写了 `ch = (q.get("channel")...` → `ch` 变成局部变量，
整个函数里赋值前使用就抛错。

**解法**：局部变量改名（`chv`），避免与模块别名冲突。

# 四、方法论沉淀

## 4.1 「能下载」≠「下载得对」

同类错误在一次任务里犯了 3 次：

1. **选到格式 ≠ 能下载**
2. **文件存在 ≠ 画质达标**
3. **能下载 ≠ 下载得对**（`format 18` 也是「下载成功」）

→ **任何健康检查都必须校验结果质量，不能只看流程跑没跑完。**

## 4.2 「改了」≠「生效了」

- `replace()` 没匹配上**不会报错**，必须 `grep` 验证
- `TaskStop` 报告「已停止」不等于进程真的退出
- 改完必须**验证产物**（文件、日志、渲染结果），而不是验证代码存在

## 4.3 `str.index()` 的锚点必须唯一

用 `s.index("某个字符串")` 做替换时，若该字符串出现多次，
会切错位置（本项目因此把 `pollParse` 函数切碎过）。

**先 `count()` 一下**：
```python
assert s.count(anchor) == 1, "锚点不唯一"
```

## 4.4 边界值不能卡死

判断「是否 1080p」时写 `h < 1080`，
把 `1920×1072`（宏块对齐后的 1080p）误判成低清。

→ 边界判断要用宽松阈值（如 `< 1000`）。

## 4.5 改布局模式要清理旧属性

`table-layout:auto` → `fixed` 时，
所有依赖 auto 才生效的属性（`max-width:0`）必须一起清理。

## 5.2 每天怎么让 AI 帮你上传

**直接说这几句就行**：

| 场景 | 你说 |
|---|---|
| 今天干完了，存一下 | 「**把今天的改动提交并推送到 GitHub**」 |
| 想看看改了啥 | 「**看看今天改了哪些文件**」 |
| 想回到某个版本 | 「**帮我回滚到上一次提交**」 |
| 换电脑了 | 「**从 GitHub 克隆这个项目到本地**」 |
| 想每天自动存 | 「**帮我配置每天自动提交推送**」 |
| 不知道改了啥 | 「**总结一下今天的改动，然后提交**」 |

**AI 会做的完整流程**（你也可以自己跑）：

```bash
git status                      # 1. 看改了什么
git add -A                      # 2. 全部暂存
git commit -m "说明这次改了什么"   # 3. 提交（本地）
git push origin main            # 4. 推到 GitHub
```

## 5.3 每天自动备份（可选）

可以配置一个**定时任务**，每天固定时间自动执行：

```
git add -A
git commit -m "每日自动备份 YYYY-MM-DD"
git push origin main
```

跟 AI 说：「**帮我配置每天 23:00 自动提交并推送这个项目到 GitHub**」即可。

> 注意：定时推送的前提是**凭证长期有效**。
> 当前凭证由 Git Credential Manager 存进 Windows 凭据管理器，
> 能不能一直用取决于当初填的 token 有没有过期。
> **哪天提示认证失败，重新登录一次即可**（或改成 SSH key，长期免维护）。
> 另外定时任务只能覆盖仓库里的代码/文档，视频本身不会自动备份。

## 5.4 为什么这样就不怕电脑资料丢了

因为代码和文档都在 **GitHub 远程仓库**：

- 本地硬盘坏了 → `git clone` 拉回来
- 换新电脑 → `git clone` 拉回来
- 改坏了 → `git log` 找到好版本，`git reset` 回去

**但注意**：`.gitignore` 里排除了媒体文件和 `tools/` 目录（体积太大），
所以**视频、歌词、Excel 不会上传**。仓库里只有代码和文档。

要备份媒体文件，得用移动硬盘或网盘。
